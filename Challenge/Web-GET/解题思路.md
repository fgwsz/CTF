# Web-GET-解题思路
打开开发者工具,查看`源代码`选项卡下的网址>索引内容:
```html
$what=$_GET['what'];<br>
echo $what;<br>
if($what=='flag')<br>
echo 'flag{****}';<br>
```
这段代码是一个典型的 **PHP 后端代码审计** 片段,
常见于 CTF(Capture The Flag,夺旗赛)的 Web 入门题.

它的功能很简单,但背后涉及 GET 传参和弱类型比较.

下面我为你逐行深度分析:

## 1. 代码逐行解析

```php
$what = $_GET['what'];   // ① 接收参数
```
- **含义**:从 URL 的查询字符串中获取名为 `what` 的参数值,并赋值给变量 `$what`.
- **示例**:如果访问 `http://xxx.com/?what=abc`,那么 `$what` 的值就是 `"abc"`.

```php
echo $what;              // ② 直接输出
```
- **含义**:将用户传入的参数值**原样**输出到 HTML 页面中.
- **风险点**:这里没有做任何过滤(如 `htmlspecialchars`),
存在**反射型 XSS(跨站脚本攻击)** 漏洞.
比如传入 `?what=<script>alert(1)</script>`,浏览器会弹窗.

```php
if($what == 'flag')      // ③ 弱类型比较
    echo 'flag{****}';   // ④ 输出 Flag
```
- **含义**:判断用户输入的内容是否**等于**(`==` 宽松比较)字符串 `"flag"`.
- **关键点**:如果条件成立,则输出真正的 Flag(此处用 `****` 做了脱敏处理).

---

## 2. 页面执行后的实际效果

假设我们以正常方式传入参数 `?what=flag`,服务端返回的 HTML 源码如下:

```html
flag<br>flag{****}
```
(注:代码中的 `<br>` 是 HTML 换行标签,不属于 PHP 逻辑)

浏览器渲染后显示为:
```
flag
flag{****}
```

---

## 3. 如何获取真正的 Flag?

根据逻辑,**只需在 URL 后面添加 `?what=flag`** 即可:
```
http://目标IP或域名/?what=flag
```
服务端会将 `$what` 赋值为 `"flag"`,`echo` 输出 `"flag"`,
随后 `if` 判断为真,输出真实的 Flag.

---

## 4. 隐藏的"坑"与考点分析(拓展)

| 考点 | 分析 |
| :--- | :--- |
| **区分大小写** | 代码中使用 `== 'flag'`,**严格区分大小写**.传入 `?what=Flag` 或 `?what=FLAG` 会判断为假,无法获取 Flag. |
| **弱类型比较(`==`)漏洞** | 虽然此处是字符串比较,但如果换成数字(如 `if($what == 0)`),传入 `?what=abc` 会因为字符串转数字变成 `0` 从而绕过.但本题是字符串 `'flag'`,无法用数字绕过. |
| **XSS 安全风险** | `echo $what` 未转义,攻击者可注入恶意脚本.但在本题中,我们只需拿 Flag,不需要利用 XSS. |

---

## 5. 总结一句话
> **这段代码的功能是:从 URL 中读取 `what` 参数,将其显示在页面上,
并判断该参数值是否严格等于字符串 `"flag"`,若是则输出隐藏的 Flag.**

因此,解题答案就是访问 `/?what=flag`.

访问`/?what=flag`后,得到如下的网页内容:
```html
$what=$_GET['what'];<br>
echo $what;<br>
if($what=='flag')<br>
echo 'flag{****}';<br>


flagflag{ae0c01efe728a094cac7dace4ca4fcd4}
flag{ae0c01efe728a094cac7dace4ca4fcd4}
```
至此,解答完毕.
