## URL 编码解码完全指南

URL 编码(又称百分号编码)是互联网传输数据时的标准转义机制,
确保非 ASCII 字符和保留字符能在 URL 中安全传输.

---

### 一|编码后字符串特征

经过 URL 编码后的字符串具有以下显著特征,可用于快速识别:

| 特征 | 描述 | 示例 |
| :--- | :--- | :--- |
| **百分号转义** | 非保留字符被替换为 `%` 后跟两位十六进制大写数字(如 `%20`|`%E4%BD%A0`). | `你好` → `%E4%BD%A0%E5%A5%BD` |
| **保留字符不动** | 字母(A-Z, a-z)|数字(0-9)以及 `-` `_` `.` `~` 保持原样(RFC 3986 保留集). | `Hello_123` → `Hello_123` |
| **空格有两种形式** | 默认使用 `%20`;若遵循 `application/x-www-form-urlencoded`(表单提交),空格编码为 `+`. | `Hello World` → `Hello%20World` 或 `Hello+World` |
| **非 ASCII 变为多字节** | 非 ASCII 字符先按 UTF-8 编码成字节序列,每个字节分别转义,因此中文字符通常产生 3 个 `%XX` 组. | `中文` → `%E4%B8%AD%E6%96%87` |
| **无换行或分隔符** | 编码后是连续的字符串,不会插入空格或换行. | 无额外空白字符 |
| **大小写敏感** | 十六进制数字通常大写(`%2F`),但标准不强制,解码时不区分大小写. | `%2f` 与 `%2F` 均代表 `/` |

---

### 二|编码原理(百分号编码算法)

URL 编码本质是将原始字符串中的每个字符,根据其类型决定保留或转义.具体步骤如下:

#### 1. 确定保留字符集
**RFC 3986** 定义了两类字符:
- **未保留字符(允许直接传输)**:  
  `A-Z`|`a-z`|`0-9`|`-`|`_`|`.`|`~`
- **保留字符(具有特殊语义)**:  
  `:`|`/`|`?`|`#`|`[`|`]`|`@`|`!`|`$`|`&`|`'`|`(`|`)`|`*`|`+`|`,`|`;`|`=`
  但这些字符仅在特定上下文中需转义,否则可视情况保留(如路径中的 `/` 可能需要保留).

#### 2. 编码流程(逐字符处理)

```
对输入字符串的每个字符 ch:
  如果 ch 属于未保留字符(字母数字 -._~):
      直接输出 ch
  否则:
      将 ch 按指定字符编码(通常 UTF-8)转换为字节序列
      对每个字节 b:
          输出 '%' + 两位十六进制大写表示(如 0x20 → "%20")
```

#### 3. 特殊:空格编码
- **默认标准**:空格(0x20)按普通字符处理,编码为 `%20`.
- **表单风格(`application/x-www-form-urlencoded`)**:空格编码为 `+`,这是一种历史惯例,常用于 HTML 表单提交和查询字符串.

#### 4. 示例演示(UTF-8 编码)

**输入**:`"Hello 世界"`

| 字符 | 是否保留 | UTF-8 字节 | 编码结果 |
| :--- | :--- | :--- | :--- |
| H | 是 | - | H |
| e | 是 | - | e |
| l | 是 | - | l |
| l | 是 | - | l |
| o | 是 | - | o |
| (空格) | 否 | 0x20 | %20 |
| 世 | 否 | 0xE4 0xB8 0x96 | %E4%B8%96 |
| 界 | 否 | 0xE7 0x95 0x8C | %E7%95%8C |

**最终输出**:`Hello%20%E4%B8%96%E7%95%8C`

---

### 三|解码原理(逆过程)

解码是编码的逆运算,目标是还原原始字符串.核心步骤如下:

#### 1. 主要规则
- 遇到 `%` 则视为转义开始:读取其后两位十六进制数字,将其转换为对应字节值.
- 非 `%` 字符直接作为普通字符(或视为 ASCII 字节).
- 对于表单风格,`+` 被还原为空格(仅当解码器启用该模式).

#### 2. 详细流程

```
对输入字符串进行遍历:
  若当前字符为 '%' 且后两位是有效的十六进制数字:
      取出两位数字,计算其数值(0-255)
      将该字节值追加到输出缓冲区
      跳过已处理的三个字符(% + 2位)
  否则若当前字符为 '+' 且解码模式允许 plus 转换:
      追加空格字符(0x20)
  否则:
      将当前字符转换为对应字节值(通常按 ASCII)追加
  继续下一个字符

遍历完成后,将累积的字节序列按指定的字符编码(如 UTF-8)解码为字符串.
```

#### 3. 重要注意事项
- **非法 `%` 序列**:如 `%G1`(非十六进制),标准要求将其原样保留或丢弃;实际实现常保留原字符,避免破坏数据.
- **多字节字符还原**:解码时不会单独处理 `%E4%B8%96`,而是将其还原为三个字节,再整体用 UTF-8 解码成"世".
- **`+` 的处理**:仅在明确要求 `plus` 模式(如处理表单数据)时才将 `+` 转空格,否则应保留为 `+`(因为 `+` 可能本身是 URL 的一部分).

#### 4. 解码示例

**输入**:`Hello%20%2B%20World%21`  
- `%20` → 空格  
- `%2B` → `+`  
- `%21` → `!`  

**输出**:`Hello + World!`

若启用 plus 模式:输入 `Hello+World` → 输出 `Hello World`.

---

### 四|常见问题与最佳实践

- **为什么推荐 UTF-8 编码?**  
  绝大多数现代应用使用 UTF-8,确保跨平台一致性.其他编码(如 GBK)可能导致互操作问题.

- **何时使用 `%20` 或 `+`?**  
  - URL 路径或普通参数中,推荐使用 `%20` 以符合 RFC 3986.  
  - `application/x-www-form-urlencoded`
(POST 表单或查询字符串的某些老实现)通常用 `+`.

- **如何选择保留字符 `safe`?**  
  若需要在 URL 中保留某些保留字符(如 `/` 或 `:`),可自定义不编码,
但需确保不破坏 URL 语义.

- **解码时的错误处理**  
  遇到无效的百分号编码或非法的 UTF-8 字节序列时,
稳健的实现应使用替换字符(如 U+FFFD)代替抛出异常,以最大限度保留数据.

### 六|一个简单的`URL`编码解码器`python`代码模板
```python
from urllib.parse import quote, unquote, urlencode

# 1. 编码/解码单个字符串
encoded_str = quote("Hello World! 你好")
print(encoded_str)  # 输出: Hello%20World%21%20%E4%BD%A0%E5%A5%BD
print(unquote(encoded_str))  # 输出: Hello World! 你好

# 2. 编码查询参数
params = {'name': '张三', 'city': 'Beijing'}
query_string = urlencode(params)
print(query_string)  # 输出: name=%E5%BC%A0%E4%B8%89&city=Beijing
```

### 总结

- **编码特征**:`%XX` 序列|保留字母数字和 `-._~`|空格可选 `%20` 或 `+`.
- **编码原理**:逐字符判断,非保留字符转 UTF-8 字节并 `%XX` 转义.
- **解码原理**:反转义 `%XX` 为字节,还原 UTF-8 字符串,并可选将 `+` 还原为空格.

掌握这些核心原理,您将能自如处理各类 URL 数据,
避免乱码和传输错误.如需更深入规范,请参阅 
[RFC 3986](https://tools.ietf.org/html/rfc3986) 和 
[WHATWG URL 标准](https://url.spec.whatwg.org/).
